# x402 pay-per-request on Stellar

nata exposes one paid endpoint as a demo of [x402](https://developers.stellar.org/docs/build/agentic-payments/x402) on Stellar: an agent calls the URL, gets `HTTP 402` with the price, signs a Soroban authorization entry for a SEP-41 token transfer, retries, and gets the data.

| | |
|---|---|
| Endpoint | `GET /api/x402/campaigns-premium` |
| Content | Active campaigns plus `fillRate`, `claimsLeft` and total remaining budget (the free `/api/campaigns` does not compute these) |
| Scheme | `exact` (`@x402/stellar`, `ExactStellarScheme`) |
| Network | `stellar:testnet` (default) or `stellar:pubnet` |
| Asset | Any SEP-41 token. Defaults to the app token (`NEXT_PUBLIC_TOKEN_CONTRACT_ID`, vUSD on testnet) |
| Default price | `0.01` token (100000 raw units, 7 decimals) |

## How it works

1. No `X-PAYMENT`/`PAYMENT-SIGNATURE` header: the route answers `402` with a `PAYMENT-REQUIRED` header (base64 JSON: scheme, network, `payTo`, token contract, amount).
2. The client (`@x402/fetch` with `@x402/stellar/exact/client`, or any x402 v2 client) signs the auth entry. It never submits a transaction.
3. The route sends the payload to the facilitator `/verify`. Only a valid payment reaches the handler.
4. If the handler answers 2xx, the facilitator `/settle` submits the transfer and pays the fee. A non-2xx answer settles nothing.

Code: `apps/web/lib/server/x402.ts` (settings, pure), `x402-gate.ts` (`withX402` wiring), `app/api/x402/campaigns-premium/route.ts`.

## Configuration (server only, see `.env.example`)

| Variable | Meaning |
|---|---|
| `X402_PAY_TO` | Receiving `G...` account. Needs a trustline to the token issuer. Unset means the route answers `503` (never serves for free). |
| `X402_ASSET` | SEP-41 contract id. Defaults to `NEXT_PUBLIC_TOKEN_CONTRACT_ID`. |
| `X402_PRICE` | Whole tokens, default `0.01`. |
| `X402_NETWORK` | `stellar:testnet` (default) or `stellar:pubnet`. |
| `X402_FACILITATOR_URL` | Default `https://www.x402.org/facilitator` (Coinbase, testnet only). OpenZeppelin: `https://channels.openzeppelin.com/x402/testnet` (testnet), `https://channels.openzeppelin.com/x402` (mainnet). |
| `X402_FACILITATOR_API_KEY` | Bearer key for the OpenZeppelin facilitator. Keep it out of git. |

## Run it end to end on testnet

You need two testnet accounts, both with a `vUSD` trustline:

- **Receiver** (`X402_PAY_TO`): any existing account, for example the merchant account. Only its public key goes in the app.
- **Payer** (`X402_CLIENT_SECRET`): holds some vUSD (use the faucet, the payer only needs about 0.01 per call). It signs an authorization entry only, so it pays no network fee: the facilitator sponsors it.

```bash
cd apps/web
# 1. app (second terminal). Use a deployed URL instead if you have one.
X402_PAY_TO=G... pnpm dev
# 2. paying client
X402_CLIENT_SECRET=S... pnpm x402:e2e
# against a deployment: X402_URL=https://<host>/api/x402/campaigns-premium
```

`pnpm x402:e2e` checks that: an unpaid call gets `402` with `exact`/`stellar:testnet` requirements and no content; a garbage payment header is refused with no content; a real payment returns `200` with the premium payload and a settled transaction hash (printed as an explorer link). The secret is read from the environment and never printed. Exit code is non-zero if any check fails.

The client only pays what the server asked for: x402 clients refuse non-USDC tokens by default, so the script allows exactly the advertised token and caps the amount at the advertised price.

### Choosing the facilitator

- **Coinbase** (`https://www.x402.org/facilitator`, default): testnet only, no API key.
- **OpenZeppelin** (`https://channels.openzeppelin.com/x402/testnet`): needs `X402_FACILITATOR_API_KEY` from <https://channels.openzeppelin.com/testnet/gen>. The existing `RELAYER_API_KEY` is for the claim relayer and should not be assumed to work here.

If the payment step fails with a verify or settle error, switch facilitator first: acceptance of the vUSD contract is documented ("any SEP-41 token") but this was not exercised on chain before the script existed.

### Vercel

Set the `X402_*` variables as server-side environment variables. The route has `maxDuration = 60`, keeps no state, and fails closed with `503` when unconfigured or when the facilitator cannot be reached.

## Agents using the nata MCP

The nata MCP server does not pay by itself (it is read-only for paid data and capped on writes). An agent pays with any x402 v2 client holding a Stellar signer, as in `apps/web/scripts/x402-e2e.mjs`: call the URL, read the `PAYMENT-REQUIRED` header, sign, retry with `PAYMENT-SIGNATURE`. The free `list_active_campaigns` tool covers the unpaid data; the premium endpoint adds `fillRate`, `claimsLeft` and total remaining budget. A `pay`-enabled MCP tool is a possible follow-up once the live round trip is confirmed.

## Tests

`pnpm test` in `apps/web` (no network, no funds) covers settings parsing, price conversion and the unpaid `402` response against an offline stub facilitator. No funds or network are needed.
